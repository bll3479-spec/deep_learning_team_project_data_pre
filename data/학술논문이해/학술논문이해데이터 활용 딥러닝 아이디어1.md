# 딥러닝 포트폴리오 프로젝트 아이디어 (투자 시간: 2일)

## 데이터 구조 요약

- 과학기술(ST)·사회과학(SS)·인문학/예술체육학(HA) 3개 대분류, 총 9편의 학술논문 (세부: 공학 2, 사회과학 3, 인문학 2, 예술체육학 1, 복합학 1)
- 각 논문마다 원천데이터로 PDF 원문 + PPTX(슬라이드 변환본) 제공
- 라벨링데이터(json)는 논문당 `raw_data_meta_info`(제목/저자/키워드/발행연도 등 서지정보) + `training_data_info` 두 종류로 구성
  - `section_info`: 문단 단위 (원문, 요약문) 쌍. 9편 합계 194개 문단 — 원문 평균 178자 → 요약 평균 29자 (압축률 약 16%)
  - `image_info`: 논문 내 그림(슬라이드에서 추출) + 그림 설명(캡션) 쌍. 9편 합계 30개, 논문당 0~8개로 편차 큼 (그림 없는 논문도 3편)
- 규모가 작은 샘플 데이터 (AI-Hub 원본 데이터셋의 일부로 추정)

## 프로젝트 아이디어 3가지

### 1. 논문 문단 추상 요약 (Abstractive Paragraph Summarization)
가장 표준적이고 데이터 활용도가 높은 프로젝트. KoBART/KoT5 같은 사전학습 한국어 seq2seq 모델을 194개 (원문, 요약문) 쌍으로 파인튜닝. Lead-1(첫 문장 추출), TextRank 추출요약을 베이스라인으로 두고 ROUGE-1/2/L, BERTScore로 비교해 "왜 파인튜닝된 생성 모델이 필요한가"를 보여주는 스토리를 만들 수 있음. 논문 도메인(공학/사회과학/인문학)별 성능 차이를 분석하면 도메인 편향에 대한 통찰도 곁들일 수 있음.

### 2. 그림-캡션 멀티모달 검색 (Image-Caption Retrieval)
CLIP류 비전-언어 모델을 활용해 그림과 캡션 텍스트를 같은 임베딩 공간에 매핑, 대조학습(contrastive learning)으로 그림→캡션 / 캡션→그림 검색을 수행. 생성(captioning)은 30쌍으로는 무리이지만, 사전학습 CLIP을 zero-shot으로 평가하고 소규모 파인튜닝(선형 프로젝션 헤드만 학습)으로 개선 여부를 보는 것은 충분히 가능. 멀티모달 경험은 채용 담당자에게 차별화 포인트가 됨.

### 3. 핵심 문단 추출 분류기 (Extractive Salience Classification)
각 문단을 "논문의 핵심 내용에 해당하는가"를 이진/순위 문제로 정의하고, 요약문과의 ROUGE 유사도를 의사 라벨(pseudo-label)로 활용해 BERT 기반 분류기를 학습. TextRank/TF-IDF 기반 전통 방법과 비교. 1번보다 구현 난이도는 낮지만 "요약 = 추출 vs 생성" 비교 스토리로 엮으면 1번의 보조 실험으로도 활용 가능.

## 추천안: 1번을 뼈대로, 여유 있으면 2번(멀티모달) 추가

### 1일차
- json에서 (문단, 요약) 194쌍 파싱, **문서 단위**로 train/val split (문단 단위로 나누면 같은 논문의 문단이 train/val에 동시에 섞여 데이터 누수 발생 — 9편이므로 K-fold 교차검증 권장)
- Lead-1 / TextRank 추출요약 베이스라인 구현
- KoBART/KoT5 파인튜닝 파이프라인 작성 및 소규모로 학습 검증

### 2일차
- 파인튜닝 완료 후 ROUGE-1/2/L, BERTScore로 베이스라인과 정량 비교, 정성 비교(생성 요약 vs 정답 vs 베이스라인 예시) 정리
- 논문 카테고리(공학/사회과학/인문학)별 성능 차이 분석
- (여유 시) CLIP zero-shot으로 30개 그림-캡션 쌍 검색 성능(Recall@k) 측정 — 파인튜닝은 데이터 부족으로 생략하거나 프로젝션 헤드만 학습
- 결과 시각화 및 README/포트폴리오 문서 작성

## 참고
샘플이 9편(194문단, 30이미지)뿐이라 딥러닝 학습만으로는 성능이 불안정할 수 있고, 특히 이미지-캡션 쌍은 파인튜닝하기엔 너무 적음. AI-Hub에 이 데이터셋의 원본 풀버전이 있을 가능성이 높으므로, 실제 학습 성능을 보여주려면 원본 다운로드를 확인해보는 것을 권함. 또한 문서 단위 split을 반드시 지켜야 데이터 누수 없는 정직한 평가가 가능함.
